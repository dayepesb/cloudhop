Una vez configurado, así es tu día: cambias la terminal a una cuenta y
escribes los comandos `aws` que ya conoces.

```text
❯ cloudhop use acme-dev
[ aws acme-dev (us-east-1) ]
❯ aws ecs list-clusters
❯ cloudhop use acme-prod
[ aws acme-prod (us-east-1) PROD ]
❯ aws s3 ls
```

Sin nombres de perfiles, sin `--profile`, sin `aws sso login`. Llegas ahí con
tres comandos.

<Aside>
`acme-dev` y `acme-prod` son alias de ejemplo. Tú eliges los nombres de los
tuyos en el paso 2, por ejemplo `billing-dev` o `data-prod`.
</Aside>

## Qué necesitas

- **Node.js 20** o más reciente, para instalar cloudhop.
- **AWS CLI v2**. ¿No lo tienes? `cloudhop doctor` te ofrece instalarlo.
- Un portal de **AWS IAM Identity Center** (una URL como
  `https://acme.awsapps.com/start`) o una **cuenta personal de AWS**.

## Configúralo

<Steps>

1. **Instala cloudhop**

   ```sh
   npm install --global cloudhop
   ```

   Obtienes dos comandos: `cloudhop` y su forma corta `hop`.

2. **Agrega tus cuentas: `cloudhop add`**

   ```sh
   cloudhop add
   ```

   <Tabs>
     <TabItem label="Portal SSO de empresa">
       Elige **IAM Identity Center (SSO portal)**, pega la URL de inicio de tu
       portal (por ejemplo `https://acme.awsapps.com/start`) y su región, y
       dale un nombre corto como `acme`.
     </TabItem>
     <TabItem label="Cuenta personal">
       Elige **Personal account (aws login)** y una región por defecto.
       Consulta [Cuentas personales](/cloudhop/es/guides/personal-accounts/)
       para saber qué necesita tu usuario.
     </TabItem>
   </Tabs>

   Se abre tu navegador: inicia sesión como siempre y aprueba. cloudhop
   lista todas las cuentas y roles que puedes usar. Marca las que quieres y
   dale a cada una un **alias**, un nombre corto con su propia región:

   ```text
   ◇  acme-production / AdministratorAccess
   ◆  Alias (what you will type)   acme-prod
   ◆  Region for acme-prod         us-east-1
   ```

   ¿Tienes varios portales? Ejecuta `cloudhop add` una vez por portal.

3. **Configura tu terminal: `cloudhop shell`**

   ```sh
   cloudhop shell
   ```

   Te pregunta y agrega una línea al archivo de inicio de tu shell
   (`~/.zshrc`, `~/.bashrc`, el `config.fish` de fish o tu perfil de
   PowerShell). Después abre una terminal nueva. Desde ahí tu terminal puede:

   - **cambiar de cuenta** con `cloudhop use <alias>`, y después escribes
     `aws` normal;
   - **iniciar sesión sola**: una sesión vencida abre el navegador y tu
     comando `aws` continúa;
   - **proteger producción**: en un alias de producción, `aws` pregunta
     antes de cualquier cosa que pueda cambiar recursos;
   - **seguir tus proyectos**: una carpeta con un `.cloudhoprc` cambia a su
     alias cuando haces `cd`;
   - **mostrar el alias en tu prompt**, incluido Starship, para que siempre
     sepas en qué cuenta estás;
   - **autocompletar alias** con <kbd>Tab</kbd>.

   <Aside title="¿Por qué una línea en mi shell?">
   Un programa no puede cambiar el entorno de la terminal que lo abrió; solo
   la shell puede. Por eso necesita esta línea. Sin ella, `cloudhop use` abre una shell nueva, y
   `hop <alias> ...` sigue funcionando.
   </Aside>

</Steps>

<Aside type="tip">
`cloudhop setup` hace los tres pasos en un recorrido guiado (y al final
puede enseñarle cloudhop a tu asistente de IA).
</Aside>

## Trabaja con `aws` como siempre

```sh
cloudhop use acme-dev          # esta terminal ahora es acme-dev (o solo `cloudhop use` para elegir)
aws sts get-caller-identity    # ¿quién soy? acme-dev
aws ecs list-clusters          # cualquier comando aws que conoces, sin cambios
terraform plan                 # Terraform, CDK y los SDKs también lo ven

cloudhop use acme-prod         # cambia de cuenta
aws s3 ls                      # ahora como acme-prod
cloudhop use --off             # vuelve a no usar ninguna cuenta
```

`cloudhop use` es el interruptor entre cuentas: pone la cuenta, el rol y la
región del alias **solo en esta terminal**. Las demás terminales conservan
la suya, así que puedes tener `acme-dev` en una pestaña y `acme-prod` en
otra. Una terminal nueva arranca sin alias; para que cada una arranque con
la cuenta que más usas, ejecuta `cloudhop use acme-dev --default`.

### Cuando una sesión vence

No tienes que hacer nada. El siguiente comando `aws` renueva la sesión en
silencio o abre tu navegador para que inicies sesión, y luego se ejecuta.
Nada revisa tus sesiones en segundo plano.

## Próximos pasos

- **Fija una cuenta a cada proyecto** con un `.cloudhoprc`, para que `cd`
  cambie por ti: [Usa un alias en tu terminal](/cloudhop/es/guides/shell/#fija-un-alias-a-una-carpeta-cloudhoprc).
- **Muestra el alias en tu prompt** (incluido Starship):
  [Mira el alias en tu prompt](/cloudhop/es/guides/shell/#mira-el-alias-en-tu-prompt).
- **Comandos puntuales en otra cuenta** sin cambiar la terminal:
  `hop acme-qa s3 ls`. Consulta [Usa hop como el comando aws](/cloudhop/es/guides/hop-like-aws/).
- **Abre la consola de AWS** con la sesión iniciada: `cloudhop console acme-dev s3`.
- **Marca los alias de producción**: `cloudhop prod acme-prod`.
- **Enséñale a tu asistente de IA**: `cloudhop agent install`.
- ¿Prefieres una página web? [`cloudhop ui`](/cloudhop/es/guides/web-ui/).
