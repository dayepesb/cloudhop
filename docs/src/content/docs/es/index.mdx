## El problema que resuelve

Varios portales SSO, decenas de cuentas con varios roles cada una, una o dos
cuentas personales. En la terminal eso significa recordar nombres de
perfiles, volver a iniciar sesión en medio del trabajo y buscar en el portal
solo para abrir la consola.

<div class="ch-pair">

```sh title="Sin cloudhop" frame="terminal"
# Una vez por cuenta y rol: escribir perfiles a mano
aws configure sso
vim ~/.aws/config

# Cada mañana, y otra vez cuando vence a mitad de algo
aws sso login --profile acme-prod

# Cada comando: el nombre exacto del perfil y la región
aws s3 ls --profile AdministratorAccess-123456789012 \
  --region us-east-1
```

```sh title="Con cloudhop" frame="terminal"
# Una vez: inicia sesión en cada portal y nombra tus cuentas
cloudhop add
cloudhop shell

# Cambia la terminal a una cuenta y escribe aws normal.
# ¿Sesión vencida? Inicia sesión por ti y sigue.
cloudhop use acme-prod
aws s3 ls
aws ecs list-clusters
```

## Dos formas de trabajar

<div class="ch-pair">
<div class="ch-panel">
<p class="ch-eyebrow">Cambia la terminal</p>

La forma del día a día. Cambias una vez y escribes `aws`,
Terraform o cualquier SDK normal. Tu prompt muestra el alias, y el
`.cloudhoprc` de un proyecto cambia por ti al hacer `cd`.

```sh frame="none"
cloudhop use acme-dev
aws ecs list-clusters
cloudhop use acme-prod
```

</div>
<div class="ch-panel">
<p class="ch-eyebrow">Un comando a la vez</p>

Para comandos puntuales en otra cuenta, o en muchas cuentas a la vez, sin
cambiar la terminal.

```sh frame="none"
hop acme-qa ecs list-clusters
cloudhop console acme-qa s3
cloudhop each 'acme-*' -- s3 ls
```

## Lo que obtienes

<div class="ch-features">
<div class="ch-feature">
<p class="ch-feature-title">Alias cortos</p>
<p>Cuenta, rol y región en una palabra. Son perfiles reales en <code>~/.aws/config</code>, así que tus otras herramientas también los ven.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Inicia sesión solo cuando hace falta</p>
<p>Una sesión vencida se renueva sola o abre tu navegador, y luego tu comando se ejecuta. Nada corre en segundo plano.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">La consola, con la sesión iniciada</p>
<p><code>cloudhop console acme-dev s3</code> la abre directo. Sin portal, sin buscar la cuenta entre veinte.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Protección de producción</p>
<p>Marca un alias como producción: las lecturas corren y todo lo que pueda cambiar recursos pregunta primero. Tu prompt se pone rojo.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Muchas cuentas a la vez</p>
<p>Ejecuta un comando en varios alias por nombre, lista, patrón o regex, en paralelo, con cada línea marcada con su alias.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Carpetas que saben su cuenta</p>
<p>Un <code>.cloudhoprc</code> fija alias a un proyecto, así <code>cd</code> cambia por ti. Apruebas cada archivo antes de que haga algo.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Tu asistente de IA lo sabe usar</p>
<p>Claude Code, Kiro, Copilot, Cursor y Codex aprenden a preguntar qué alias usar, ejecutar con <code>hop</code> y confirmar antes de cambiar algo.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Nunca access keys</p>
<p>Solo credenciales temporales, de IAM Identity Center o <code>aws login</code>. Nada que rotar, nada que se filtre.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Terminal o navegador</p>
<p>¿Prefieres hacer clic? <code>cloudhop ui</code> abre una página local para agregar portales, elegir cuentas y cambiar regiones.</p>
</div>

## Todos los comandos `aws` que conoces, de dos formas

`acme-dev` y `acme-prod` son alias de ejemplo: tú les pones nombre a los
tuyos cuando agregas tus cuentas. La salida, los pipes, `--query` y los
códigos de salida funcionan exactamente igual que con `aws`.

| Solo con el AWS CLI | Cambiando la terminal | Nombrando el alias en el comando |
| --- | --- | --- |
| `aws s3 ls --profile AdministratorAccess-123456789012` | `cloudhop use acme-prod`<br/>`aws s3 ls` | `hop acme-prod s3 ls` |
| `aws sts get-caller-identity --profile acme-prod` | `aws sts get-caller-identity` | `hop acme-prod` |
| `aws logs tail /app --follow --profile acme-dev` | `aws logs tail /app --follow` | `hop acme-dev logs tail /app --follow` |
| `AWS_PROFILE=acme-prod terraform plan` | `terraform plan` | `cloudhop exec acme-prod -- terraform plan` |

Después de `cloudhop use`, todos los comandos siguientes corren como ese
alias hasta que cambies otra vez. `hop <alias>` afecta solo ese comando.

## Empieza en un minuto

<Steps>

1. Instálalo (Node.js 20 o más reciente):

   ```sh
   npm install --global cloudhop
   ```

2. Agrega tu portal SSO o cuenta personal: inicias sesión, marcas las
   cuentas que quieres y le das a cada una un alias corto.

   ```sh
   cloudhop add
   ```

3. Configura tu terminal, una sola vez. Luego abre una nueva.

   ```sh
   cloudhop shell
   ```

4. Cambia a una cuenta y usa `aws` como siempre (`<alias>` es un nombre que
   pusiste en el paso 2):

   ```sh
   cloudhop use <alias>
   aws s3 ls
   ```

</Steps>
