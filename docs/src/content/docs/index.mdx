## The problem it solves

If you work with AWS at a company, you probably have several SSO portals,
dozens of accounts and a few roles in each, plus a personal account or two.
Using them from the terminal means a lot of ceremony:

<Tabs>
  <TabItem label="Without cloudhop">
    ```bash
    # Once per portal, by hand: profiles for every account and role you use
    aws configure sso                       # repeat for each account/role...
    vim ~/.aws/config                       # ...or edit dozens of profiles by hand

    # Every morning, and again whenever a session expires mid-task
    aws sso login --profile acme-prod

    # Every command: remember the exact profile name and region
    aws s3 ls --profile AdministratorAccess-123456789012 --region us-east-1

    # Personal accounts: long-lived access keys in ~/.aws/credentials
    ```
  </TabItem>
  <TabItem label="With cloudhop">
    ```bash
    # Once per portal: sign in, tick the accounts you want, name them
    cloudhop add

    # Every command: a short alias that already knows account, role and region
    hop acme-prod s3 ls

    # Expired session? Nothing to do: cloudhop signs you in again and runs it
    ```
  </TabItem>
</Tabs>

No more copied keys, no more hand-written profiles, no more "the SSO session
has expired" in the middle of your work.

## How it works

<Steps>

1. **You add a source once.** A company SSO portal (IAM Identity Center) or
   your personal account. cloudhop signs you in through the browser, exactly
   like the AWS CLI does.

2. **You pick accounts and name them.** cloudhop lists every account and role
   you can use; the ones you choose become aliases, each with its own region.
   They are written as normal profiles in `~/.aws/config`.

3. **You use `hop <alias>` instead of `aws`.** cloudhop checks the session
   (renewing it silently or opening the browser only if it really expired),
   then runs the AWS CLI with that alias' profile and region.

</Steps>

## Just like the `aws` command

`hop <alias>` **is** the AWS CLI: everything after the alias goes to `aws`
untouched. Take any `aws` command you know, replace `aws` with `hop <alias>`,
and drop `--profile`:

| With the AWS CLI | With cloudhop |
| --- | --- |
| `aws s3 ls --profile acme-prod` | `hop acme-prod s3 ls` |
| `aws sts get-caller-identity --profile acme-prod` | `hop acme-prod` |
| `aws ec2 describe-instances --profile acme-prod --region eu-west-1` | `hop acme-prod ec2 describe-instances --region eu-west-1` |
| `aws logs tail /app --follow --profile acme-dev` | `hop acme-dev logs tail /app --follow` |
| `AWS_PROFILE=acme-prod terraform plan` | `cloudhop exec acme-prod -- terraform plan` |

Output, pipes, `--output json`, `--query` and exit codes behave exactly as
with `aws`. More in [Use hop like the aws command](guides/hop-like-aws/).

## From zero to your first command

```bash
npm install --global cloudhop
cloudhop setup                 # add your SSO portal, sign in, pick accounts
hop acme-prod s3 ls            # runs `aws s3 ls` as that account, role and region
```

That's it. Next week, when the session has expired, `hop acme-prod s3 ls`
signs you in again by itself and then runs your command.

## Your AI assistant knows it too

Claude Code, Kiro, GitHub Copilot, Cursor and Codex can run cloud commands for
you. Teach them cloudhop once:

```bash
cloudhop agent install
```

From then on your assistant asks which alias to use, checks the session, runs
commands with `hop` and confirms before changing anything, in every new chat.
See [AI assistants](guides/ai-assistants/).

## Why cloudhop

<CardGrid stagger>
  <Card title="One login per portal" icon="rocket">
    Sign in once to each IAM Identity Center portal. cloudhop finds every
    account and role you can use and turns the ones you pick into aliases.
  </Card>
  <Card title="Logs in only when needed" icon="approve-check">
    Nothing runs in the background. When you use an alias with an expired
    session, cloudhop renews it silently or opens the browser, then carries on.
  </Card>
  <Card title="No access keys, ever" icon="seti:lock">
    Only temporary credentials: IAM Identity Center for companies, `aws login`
    for personal accounts. Nothing to rotate, nothing to leak.
  </Card>
  <Card title="Works with your tools" icon="puzzle">
    Aliases are real profiles in `~/.aws/config`, so Terraform, the SDKs and
    your IDE see them too. `cloudhop exec` covers everything else.
  </Card>
  <Card title="Terminal or browser" icon="laptop">
    Prefer clicking? `cloudhop ui` opens a local page to add portals, pick
    accounts and change regions.
  </Card>
  <Card title="Open source" icon="open-book">
    Apache 2.0, built in the open, published to npm with provenance from
    GitHub Actions.
  </Card>
</CardGrid>
