## From zero to your first command

```bash
npm install --global cloudhop
cloudhop setup                 # add your SSO portal, sign in, pick accounts
hop acme-prod s3 ls            # runs `aws s3 ls` as that account, role and region
```

That's it. Next week, when the session has expired, `hop acme-prod s3 ls`
signs you in again by itself and then runs your command.

## Why cloudhop

<CardGrid stagger>
  <Card title="One login per portal" icon="rocket">
    Sign in once to each IAM Identity Center portal. cloudhop finds every
    account and role you can use and turns the ones you pick into aliases.
  </Card>
  <Card title="Logs in only when needed" icon="approve-check">
    Nothing runs in the background. When you use an alias with an expired
    session, cloudhop renews it silently or opens the browser, then carries on.
  </Card>
  <Card title="No access keys, ever" icon="seti:lock">
    Only temporary credentials: IAM Identity Center for companies, `aws login`
    for personal accounts. Nothing to rotate, nothing to leak.
  </Card>
  <Card title="Works with your tools" icon="puzzle">
    Aliases are real profiles in `~/.aws/config`, so Terraform, the SDKs and
    your IDE see them too. `cloudhop exec` covers everything else.
  </Card>
  <Card title="Terminal or browser" icon="laptop">
    Prefer clicking? `cloudhop ui` opens a local page to add portals, pick
    accounts and change regions.
  </Card>
  <Card title="Open source" icon="open-book">
    Apache 2.0, built in the open, published to npm with provenance from
    GitHub Actions.
  </Card>
</CardGrid>
