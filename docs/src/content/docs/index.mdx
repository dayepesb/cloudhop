## The problem it solves

Several SSO portals, dozens of accounts with a few roles each, a personal
account or two. From the terminal, that means remembering profile names,
logging in again in the middle of your work, and digging through the portal
just to open the console.

<div class="ch-pair">

```sh title="Without cloudhop" frame="terminal"
# Once per account and role: write profiles by hand
aws configure sso
vim ~/.aws/config

# Every morning, and again when it expires mid-task
aws sso login --profile acme-prod

# Every command: the exact profile name and region
aws s3 ls --profile AdministratorAccess-123456789012 \
  --region us-east-1
```

```sh title="With cloudhop" frame="terminal"
# Once: sign in to each portal, name your accounts
cloudhop add
cloudhop shell

# Switch the terminal to an account, type plain aws.
# Expired session? It signs you in and carries on.
cloudhop use acme-prod
aws s3 ls
aws ecs list-clusters
```

</div>

## Two ways to work

<div class="ch-pair">
<div class="ch-panel">
<p class="ch-eyebrow">Switch the terminal</p>

The everyday way. Switch once and type plain `aws`,
Terraform or any SDK. Your prompt shows the alias, and a project's
`.cloudhoprc` switches for you on `cd`.

```sh frame="none"
cloudhop use acme-dev
aws ecs list-clusters
cloudhop use acme-prod
```

</div>
<div class="ch-panel">
<p class="ch-eyebrow">One command at a time</p>

For one-off commands in another account, or many accounts at once,
without switching the terminal.

```sh frame="none"
hop acme-qa ecs list-clusters
cloudhop console acme-qa s3
cloudhop each 'acme-*' -- s3 ls
```

## What you get

<div class="ch-features">
<div class="ch-feature">
<p class="ch-feature-title">Short aliases</p>
<p>Account, role and region in one word. They are real profiles in <code>~/.aws/config</code>, so your other tools see them too.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Signs in only when needed</p>
<p>An expired session renews silently or opens your browser, then your command runs. Nothing runs in the background.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">The console, already signed in</p>
<p><code>cloudhop console acme-dev s3</code> opens it straight away. No portal, no hunting for the account among twenty.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Production protection</p>
<p>Mark an alias as production: reads run, anything that may change resources asks first. Your prompt turns red.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Many accounts at once</p>
<p>Run one command across aliases by name, list, pattern or regex, in parallel, with every line tagged by alias.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Folders that know their account</p>
<p>A <code>.cloudhoprc</code> pins aliases to a project, so <code>cd</code> switches for you. You approve each file before it does anything.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Your AI assistant knows it</p>
<p>Claude Code, Kiro, Copilot, Cursor and Codex learn to ask which alias, run with <code>hop</code> and confirm before changes.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">No access keys, ever</p>
<p>Only temporary credentials, from IAM Identity Center or <code>aws login</code>. Nothing to rotate, nothing to leak.</p>
</div>
<div class="ch-feature">
<p class="ch-feature-title">Terminal or browser</p>
<p>Prefer clicking? <code>cloudhop ui</code> opens a local page to add portals, pick accounts and change regions.</p>
</div>
</div>

## Every `aws` command you know, two ways

`acme-dev` and `acme-prod` are example aliases: you name yours when you add
your accounts. Output, pipes, `--query` and exit codes behave exactly as
with `aws`.

| With the AWS CLI alone | Switching the terminal | Naming the alias in the command |
| --- | --- | --- |
| `aws s3 ls --profile AdministratorAccess-123456789012` | `cloudhop use acme-prod`<br/>`aws s3 ls` | `hop acme-prod s3 ls` |
| `aws sts get-caller-identity --profile acme-prod` | `aws sts get-caller-identity` | `hop acme-prod` |
| `aws logs tail /app --follow --profile acme-dev` | `aws logs tail /app --follow` | `hop acme-dev logs tail /app --follow` |
| `AWS_PROFILE=acme-prod terraform plan` | `terraform plan` | `cloudhop exec acme-prod -- terraform plan` |

After `cloudhop use`, every following command runs as that alias until you
switch again. `hop <alias>` affects only that one command.

## Start in a minute

<Steps>

1. Install it (Node.js 20 or newer):

   ```sh
   npm install --global cloudhop
   ```

2. Add your SSO portal or personal account: sign in, tick the accounts you
   want and give each a short alias.

   ```sh
   cloudhop add
   ```

3. Set up your terminal, once. Then open a new one.

   ```sh
   cloudhop shell
   ```

4. Switch to an account and use `aws` as always (`<alias>` is a name you
   gave in step 2):

   ```sh
   cloudhop use <alias>
   aws s3 ls
   ```

</Steps>
